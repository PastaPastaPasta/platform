# Mining proof integration validation

This branch implements `DASHNC02` from DIP PR 175. Core PR 7107 generates the
proofs; DAPI and the quorum server relay identical binary bootstrap envelopes.
Mainnet/testnet SDK builders use independently pinned snapshots and verify Core
quorum evidence by default. Explicit trusted context providers skip the Core
proof stage. No service deployment is included.

## Validation scope

The shared verifier consumes real testnet evidence, including mining-to-certificate
ancestor gaps. The tests reject altered signatures, headers, roots, records,
requested quorum identities, noncanonical encodings, invalid BLS subgroups and
oversized responses. Mainnet snapshot identity and roots are checked against a
complete coinbase with an authenticated transaction path; snapshot provenance is
recorded beside the embedded checkpoints.

The HTTP provider tests run a local relay, test failover, verify exact binary
records, and check that failed evidence cannot partially publish keys/state.
The browser test executes the real proof through Fetch/ReadableStream in Node's
WebAssembly runtime and rejects a body exceeding the decoded limit without
Content-Length. DAPI's local RPC fixture checks byte-preserving relay, cache reuse,
request validation and worker saturation.

Recorded local results:

- Core: complete Apple ARM64 build after merging `develop` at `30a87486af47`;
  six proof unit tests; RPC verification and index/restart functional test;
  format-string and suite-name lint.
- Shared Rust verifier: native and Node WebAssembly fixture/adversarial tests.
- DAPI: 308 unit tests.
- Shared trusted/verified context provider: 22 native tests and one streamed
  WebAssembly transport test.
- Rust SDK: 188 unit tests, including verified defaults and explicit trusted
  provider precedence; native SDK and WASM SDK compile checks.
- JavaScript: TypeScript build, production webpack build, 223 Node and 223 Chrome unit tests,
  targeted ESLint; gateway template rendering test.

This is not an end-to-end mainnet proof generated by the new RPC on an archive
node. The service endpoints must be deployed and validated before releasing the
new SDK default to users. Current proof/key caches last for the SDK session.

## Review

The code-review-validator passes covered actual changes for correctness,
maintainability, architecture and security. Fixes include independently supplied
anchors, atomic cache publication, exact requested quorum matching, cumulative
allocation limits, canonical Merkle/BLS decoding, typed asynchronous cache misses,
browser cancellation, and blocking RPC workers retaining capacity after timeouts.
Core retains multiple-chainstate commitment lifetime handling and reconstructs
missing/stale mining witnesses from archived blocks.

The code-simplifier pass removed retired Core commitment helpers and reused
existing BLS/X11 implementations. It also isolated proof acquisition from generic
SDK query futures to reduce duplicate generated machine code. All verification
checks remain in place.

Approval status: APPROVED WITH SUGGESTIONS for branch review. Live mainnet archive
RPC generation and deployed SDK-to-service validation remain release gates.

The security model assumes historical ChainLock keys remain honest. It does not
independently replay DKG, full consensus or exact signer eligibility. Relays cannot
supply replacement trusted roots. The SDK's signed-time/height policies address
freshness; a proof alone does not establish the globally newest tip.
